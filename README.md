# 우리팀 허브

팀 소통·공지를 한 화면에서 보는 웹앱입니다. 휴대폰·PC 어디서든 열 수 있고, 홈 화면에 추가하면 앱처럼 쓸 수 있습니다.

- **바로 열기:** https://leanonmept.github.io/team-hub/
- **만든 방식:** 단일 HTML 파일(`index.html`) — 별도 빌드 없이 GitHub Pages로 서빙됩니다.

## 화면

- **공지** — 공지 작성·고정·중요 표시, 댓글, 읽음 확인
  - **🔍 공지 검색** — 공지 탭 위 `🔍 공지 제목·내용 검색` 칸에 입력하면 제목·본문·작성자를 실시간으로 걸러 보여주고, 찾은 글자는 노란 형광으로 표시됩니다. `✕`를 누르면 전체 목록으로 돌아가고, 고정/필독/안 읽음 칩과 함께 써도 됩니다.
  - **오늘의 팀 한 줄** — 공지 탭 맨 위에 오늘 날짜와 함께 `🏢 당직 · 🌙 1박 섬 · ⛴️ 당일 섬 · 📚 교육` 담당자, 오늘 행사가 한 줄로 뜹니다. 누르면 당직 탭으로 이동. 일정이 없으면 `✨ 오늘 당직·섬·교육 일정 없음`
  - **📊 간단 투표** — 공지 작성/수정 시 `📊 투표 첨부`를 켜면 투표 질문과 선택지 2~6개, 복수 선택 허용을 정할 수 있습니다. 목록 카드에는 `📊 투표 진행중 · N명 참여` 배지와 선택지별 미니 막대, 상세에서는 선택지를 눌러 바로 투표·변경·취소하고 득표수·비율 막대와 **누가 어디에 투표했는지 이름**까지 실시간으로 보입니다.
- **당직** — 🏢 당직 달력과 ⛴️ 섬·교육 달력을 탭으로 분리
  - 🏢 당직: 월~금 5열 달력(큰 이름 배지) · 🖨️ 인쇄(당직표 인쇄·저장 시트 — 보고 있는 달을 A4 가로 PNG 2200×1554로 그려 미리보기로 보여주고 📤 공유/아이폰 인쇄 · 🖼️ 이미지 저장 · 🖨️ 바로 인쇄 중에 고름. 아이폰 홈 화면 앱에서는 window.print()가 막히므로 공유 시트의 프린트·파일에 저장을 씀. 당직자·공휴일·행사일·등판만 넣고 의소기한·조사기한은 앱 화면에만) · 공휴일 자동 연동(빨간 날짜 + 공휴일명) · 당직 명단(가나다순, 제외/포함, 회원이 아닌 사람 직접 추가·수정·삭제 · 같은 이름으로 가입·승인되면 직접입력 당직을 회원 계정으로 자동 이동 — 같은 날 중복은 1건만, 알림 없음) · 매월 24일 0시 이후 첫 접속 때 다음 달 자동 배정 · 재배정(시작 날짜와 시작 담당자를 골라 그날부터 순번을 다시 돌린 결과를 기존 담당자와 비교한 뒤 적용) · 행사일(등록하면 그날 당직 취소 + 달력 칸 전체 연보라 음영에 행사명 표시) · 팀원끼리 담당자 변경(한 날짜 1명, 바꾸면 기존 담당자 교체 + 변경 이력) · 칸 맨 위 당직자 아래에 등판(빨강)·의소기한(파랑)·조사기한(초록) 자동 표시(등판 2026-12-09부터 격주 수요일, 의소기한 전주 목요일, 조사기한 하루 전 · 관리자·당직 관리 권한자는 날짜 상세에서 붙이거나 뺄 수 있음)
  - ⛴️ 섬·교육: 일~토 7열 달력에 당일 섬 · 1박 섬 · 교육 일정. 여러 날 일정(1박 섬·연속 교육)은 주 안에서 가로 막대로 이어서 표시
  - **⛴️ 섬 2인 1조 동시 등록** — 섬은 보통 2인 1조로 함께 가므로, 새 일정을 등록할 때 담당자를 **여러 명 골라(칩 토글) 같은 날짜·같은 섬(장소)·메모로 한 번에 저장**합니다. 고른 인원은 `2명 선택됨 · 2인 1조`처럼 표시되고 저장 버튼도 `2명 일정 등록`으로 바뀝니다. 1명만 골라 저장해도 되고 3명 이상도 됩니다. `＋ 직접입력`으로 명단에 없는 이름을 그 자리에서 추가해 함께 넣을 수 있고(관리자·당직 관리 권한자), `교육` 일정은 기존처럼 1명씩 등록합니다. 저장은 인원별로 기존 일정 문서(`duty_schedules`, id=날짜_담당자_종류)를 그대로 써서 달력·통계·직접입력 자동 병합과 호환되며, 섬 일정은 예전처럼 알림을 보내지 않습니다.
  - **🖋️ 간사·간사보조 당직 겹침 방지** — 간사·간사보조로 지명된 분들은 **같은 날짜에 당직으로 함께 잡히지 않게** 자동 배정·재배정·수동 변경에서 막습니다. ① 자동 배정·재배정은 그 날이 이미 다른 지명자의 당직이면 그 사람을 지우지 않고 그대로 두고(토스트에 `지명자 겹침 회피 N일`), ② 수동으로 지명자를 그 날에 넣거나 섬 2인 1조로 둘을 함께 고르면 `간사·간사보조는 같은 날 등판하지 않는 것이 원칙` 확인창이 뜨며, ③ 이미 두 지명자가 같은 날 잡혀 있는 데이터는 당직 달력 위 빨간 ⚠️ 안내와 날짜 상세 경고로 알려 줍니다. 당직이 원래 **한 날짜 1명**인 앱에서는 정상 배정으로는 겹칠 수 없으므로, 위 규칙은 수동·예전 데이터·동시 저장 같은 예외 상황을 잡는 안전장치입니다.
- **사진** — 팀 사진 공유 · **여러 장 동시 업로드** · **갤러리 스타일 앨범**
  - **📸 여러 장 올리기** — 사진 올리기에서 `📷 사진 선택 (여러 장 가능)`으로 한 번에 10장까지 고를 수 있습니다. 고른 사진은 썸네일 그리드로 보이고 `✕`로 하나씩 빼거나 더 담을 수 있으며, 앨범과 한 줄 메모를 정해 올리면 기존과 똑같이 압축(가로 960px · JPEG 0.72)되어 한 장씩 저장됩니다. 올리는 동안 버튼에 `1/5 올리는 중…`처럼 진행률이 뜨고, 중간에 실패해도 이미 올라간 사진은 빼고 남은 것만 다시 시도합니다.
  - **🖼️ 앨범 (갤러리 스타일)** — 사진 탭은 **2열 앨범 커버 그리드**로 시작합니다. 위에 `＋ 새 앨범` · `＋ 올리기` 버튼이 있고, 카드에는 앨범의 **최신 사진 썸네일**(비어 있으면 조용한 플레이스홀더) · 앨범 이름 · `N장`이 나옵니다. 맨 앞은 **🖼️ 전체 사진**(최신 사진 + 전체 장수), 앨범이 없는 사진은 **🗂️ 미정리** 카드로 모입니다.
    - **앨범 안 보기** — 앨범 카드를 누르면 `← 앨범 목록` · 앨범 제목 · 장수 · `＋ 이 앨범에 올리기` · 관리(이름 변경 / 사진 비우기 / 앨범 삭제 — 관리자 또는 만든 사람)와 함께 **그 앨범 사진만 3열 그리드**로 보입니다. `＋ 이 앨범에 올리기`는 올리기 시트에 그 앨범이 이미 선택된 상태로 열려 바로 담깁니다.
    - **＋ 새 앨범** — `11월 백령도`, `연말 회식`처럼 이름을 넣어 만듭니다. 관리자·당직 관리 권한자가 만들면 `duty_roster_config/config.photoFolders` 에 저장되어 **사진이 없어도 팀원 모두에게 바로 보이고**, 일반 팀원이 만들면 이 기기에 먼저 생겨 업로드 앨범으로 바로 쓰이며 그 앨범으로 사진을 올리는 순간 `folder` 필드로 팀원 모두에게 보입니다.
    - **올릴 때 앨범 고르기** — 앨범 안에서 올리면 그 앨범이, 앨범 목록에서 올리면 `🗂️ 미정리`가 기본 선택됩니다. `미정리` · 기존 앨범 · `＋ 새 앨범 직접 입력` 중에서 고를 수 있고, 시트 안에서 만든 앨범도 바로 목록에 잡힙니다.
    - **정리** — 이름을 바꾸면 그 앨범 사진이 새 이름으로 함께 옮겨지고, 비우면 사진이 `미정리`로 가고 앨범은 남습니다. 사진 상세에서는 올린 사람·관리자가 `앨범 옮기기`로 한 장씩 다른 앨범으로 옮길 수 있습니다.
    - **기존 데이터** — 앨범이 없던 예전 사진은 `전체 사진`과 `미정리`에 그대로 보입니다. 저장 필드(`photos.folder` · `photoFolders`)는 그대로라 보안 규칙은 다시 게시하지 않아도 됩니다.
- **🍽️ 맛집** — 팀 공유 맛집 지도. `🗺️ 지도`(**카카오맵** JavaScript SDK — 앱에 기본 JS 키가 내장돼 있고, 키가 없거나 SDK 로드에 실패하면 키 없는 깔끔한 기본 지도(Esri → OpenStreetMap)로 자동 대체)와 `📋 목록` 전환. 등록은 **🔍 가게 검색 → 지도(핀) → 가게명·주소 → 지역 → 별점 → 한줄평 및 추천메뉴** 순서로, 가게 이름으로 검색해 후보를 누르면 가게명·주소·지도 위치가 한 번에 채워집니다. **지도(핀)와 별점(0.5~5.0, 별 좌/우 반 탭 또는 별 줄을 좌우로 드래그·스와이프해 0.5점 단위로 조절)은 필수**, **한줄평 및 추천메뉴는 선택**. 카드에서 ❤️ 좋아요와 **네이버지도**(기본) · 카카오맵 바로 열기, 작성자·관리자는 수정·삭제. 지도 핀을 누르면 인포윈도/팝업으로 같은 정보와 지도 열기 버튼이 뜨고, 핀이 화면 아래쪽에 오도록 지도를 살짝 옮겨 안 잘리게 열립니다.
  - **카카오 장소 검색** — 앱에 **기본 REST API 키**가 내장되어 있어 따로 설정하지 않아도 맛집 등록의 검색창에서 `신포우리만두` 같은 **상호명·키워드**로 찾아 후보(상호명 · 도로명/지번주소 · 카테고리 · 전화) 최대 8개를 보여주고, 하나를 누르면 가게명·주소·지도 핀 좌표가 한 번에 채워집니다. 관리자가 [팀원관리 → 관리 → 카카오 장소 검색 키]에 다른 키를 넣으면 그 키를, 지우면 다시 기본 키를 쓰며(관리 메뉴에는 `연결됨 (기본 키)`로 표시), 직접 넣은 키는 `duty_roster_config/config.kakaoRestKey`에 들어가 승인된 팀원 모두가 함께 쓰고 보안 규칙 변경·재게시는 필요 없습니다. 카카오 응답이 401/403이면 키 확인 안내를 보여줍니다.
  - **카카오맵 화면 키(JS 키)** — 같은 관리 메뉴에서 `duty_roster_config/config.kakaoJsKey`로 바꿀 수 있습니다(기본 키 내장). 카카오 developers → 내 애플리케이션 → 플랫폼 → **Web 사이트 도메인**에 `https://leanonmept.github.io`가 등록돼 있어야 카카오맵이 뜨고, 등록 전에는 기본 지도로 자동 대체됩니다.
  - **지역 분류 + 필터 칩 (영종구 · 제물포구 · 옹진군 · 기타)** — 음식 종류(한식·분식·중식·일식·양식·카페) 자동 분류와 종류 칩은 없앴습니다. `🍽️ 맛집` 탭 지도·목록 위 칩은 `전체 · ✈️ 영종구 · ⚓ 제물포구 · ⛴️ 옹진군 · 🗺️ 기타` 이고, 카드와 지도 핀 팝업에 지역 배지가 붙습니다.
    - **주소로 자동 판별** — 등록할 때 카카오 장소 검색으로 주소를 고르면 지역 칩이 자동으로 정해집니다. `옹진군`(옹진 포함) → 옹진군, `영종구` 또는 중구의 영종 지역(`운서·운남·운북·중산·을왕·남북·덕교·무의·영종`) → 영종구, `제물포구`·`동구`·그 밖의 중구(`신포·신흥·선린·북성·송월·연안·항동·율목·도원·인현·내동·경동·중앙동·관동·해안동·사동·답동·송학동·전동·월미` 등) → 제물포구, 그 외 → 기타. 구 이름은 토큰으로 비교해 `남동구·서구` 같은 다른 구를 중구·동구로 잘못 보지 않습니다.
    - 칩을 눌러 **직접 바꿀 수도 있고**(예: 영종구 → 옹진군), 저장은 `region` 필드로 합니다(보안 규칙 재게시 불필요). 지역이 없던 예전 데이터는 저장된 주소로 추론하고, 주소도 없으면 `기타`로 보입니다.
  - 예전 데이터의 구분(지사 주변·섬/출장지·회식/모임)·음식 종류(`category`·`cat`)·추천 메뉴 값은 지우지 않고, 구분만 있을 때 카드·팝업에 표시합니다(음식 종류는 표시하지 않음).
- **대화** — 팀 단체방
- **팀원·설정** — 하단 탭이 아니라 **상단 오른쪽 프로필 아이콘**을 눌러 들어갑니다(돌아가기는 화면 위 `← 돌아가기` 또는 하단 5탭 아무거나). 팀원 승인, 직책(주임·대리·과장·팀장·센터장·부장) 변경, 관리자/당직 관리 권한 부여·해제, 내 프로필 사진·이모티콘 변경
  - **관리자는 본인 직책도 바꿀 수 있습니다** — 팀원 목록에서 내 이름을 눌러 `내 직책`에서 고르거나, [내 정보] 시트의 `내 직책`에서 고르면 바로 저장됩니다(`users/{uid}.position`, 앱 권한과는 별개). 다른 팀원의 직책은 예전처럼 내 카드의 `직책 · 권한 관리`에서 관리자가 바꿉니다.
  - **🖋️ 간사 · 간사보조 지명** — 관리자가 팀원 목록에서 회원 카드를 누르면 `🖋️ 간사 · 간사보조 지명`에서 **간사 / 간사보조 / 지명 안 함**을 고를 수 있습니다(각 1명, 한 사람이 둘을 겸하지 않음). 다른 분이 이미 그 자리를 맞고 있으면 `○○ 님 대신 △△ 님으로 바꿀까요?`라고 먼저 물어봅니다. 저장은 `users/{uid}.execRole`(‘secretary’·‘assistant’·‘’)로 하고, 관리자의 users 수정은 보안 규칙에서 필드 제한이 없어 **규칙 재게시가 필요 없습니다**. 지명되면 팀원 목록·회원 카드·내 정보·당직 명단·날짜 상세에 보라색(간사보조는 하늘색) `🖋️ 간사` 배지가 붙고, 당직 달력의 그 사람 이름 칸에는 보라 테두리가 생깁니다.
  - 관리자에게 승인 대기 신청이 있으면 프로필 아이콘 오른쪽 위에 빨간 숫자 배지가 뜹니다.
  - 하단 탭은 **공지 · 당직 · 사진 · 맛집 · 대화** 5개입니다. 거절된 가입 신청은 카드를 **왼쪽으로 밀면** 빨간 `🗑️ 삭제` 버튼이 나오고, 누르면 신청 기록이 지워집니다(PC에서는 마우스로 끌어도 됩니다).

## 처음 설정하기

앱에는 Firebase 프로젝트 **`team-hub-8d819`** 의 웹 앱 설정값이 이미 들어 있습니다. 아래 콘솔 설정만 끝나면 별도 입력 없이 실시간 모드로 연결됩니다. (설정이 끝나기 전에는 로그인 화면 맨 아래 **체험 모드로 둘러보기**로 화면만 미리 볼 수 있습니다. 체험 모드는 이 기기에만 저장됩니다.)

1. Firebase 콘솔에서 Authentication을 시작하고 **이메일/비밀번호** 로그인을 켭니다. (앱은 로그인에 쓰는 사번을 `사번@teamhub.local` 가상 이메일로 바꿔서 씁니다 — 사용자에게는 이메일이 보이지 않습니다.)
2. Authentication → Settings → **승인된 도메인**에 `leanonmept.github.io`를 추가합니다.
3. Firestore Database를 만듭니다. 데이터베이스 ID는 기본값 **`(default)`** 그대로, 위치는 `asia-northeast3` 서울 권장.
4. 이 저장소의 [`firebase-rules.txt`](firebase-rules.txt) 내용을 Firestore 규칙 탭에 붙여넣고 게시합니다.
5. 첫 관리자 지정 — 규칙의 `isBootstrap()` 이메일을 본인 사번(`사번@teamhub.local`)으로 채워 게시한 뒤 그 사번으로 가입하면 처음부터 관리자/승인 상태가 됩니다. 이미 가입했다면 콘솔 Firestore의 `users/{uid}` 문서에서 `role='admin'`, `status='approved'`로 고칩니다. (현재 규칙은 첫 가입자를 자동으로 관리자로 만들지 않습니다.)
6. 다른 Firebase 프로젝트로 바꾸려면 앱 → 팀원·설정 → **Firebase 연결 설정**에서 값을 바꿔 저장합니다. 비우고 저장하면 기본(`team-hub-8d819`) 연결로 돌아갑니다.

## 참고

- **바텀 시트 끌어내려 닫기** — 명단·섬 파고·설정 등 모든 바텀 시트는 위쪽 핸들이나 제목 줄을 **아래로 끌면** 손가락을 따라 내려오고, 90px 이상 내리거나 빠르게 튕기면 닫힙니다. 시트 본문에서 끌 때는 **스크롤이 맨 위일 때만** 시트가 내려오고, 스크롤이 내려가 있으면 본문만 스크롤됩니다. ✕ 버튼과 어두운 배경 탭 닫기도 그대로입니다.
- **오프라인 캐시(`sw.js`)** — 앱은 서비스 워커로 화면(`index.html`)과 아이콘을 이 기기에 캐시합니다. 섬·출장지에서 전파가 약해도 화면이 바로 뜨고, 새 배포가 있으면 백그라운드에서 새 화면을 받아 두고 상단에 `🔄 새 버전이 있어요 · 눌러서 새로고침`을 띄웁니다. 캐시 전략을 바꾸면 `sw.js`의 `SW_VERSION`을 올려 주세요(올리면 기존 캐시는 자동으로 지워집니다). Firebase·기상청·카카오 등 외부 주소는 캐시하지 않고 그대로 네트워크로 보냅니다.
- **🔔 새 소식 배지** — 마지막으로 확인한 시점(`localStorage`의 `teamhub.seen.{uid}`)을 이 기기에 저장해 두고, 그 뒤에 올라온 **새 공지**와 **내 당직·섬·교육 일정 변경(신규·수정·교대/취소)**을 하단 탭 빨간 배지와 상단 안내 배너로 알려 줍니다. 배너를 누르면 해당 화면으로 이동하고, `✕`로 이번 소식만 닫을 수 있습니다. 기기를 바꾸면 그 기기 기준으로 새로 시작합니다(서버 푸시가 아니라 앱을 열었을 때 알려 주는 방식).
- **⛴️ 오늘 실제 운항** — 섬 파고·배편 시트의 `오늘 실제 운항`은 공공데이터포털 오픈API **15142302 한국해양교통안전공단 운항 스케줄 정보**(`apis.data.go.kr/B554035/oprt-schd-info-v2/get-oprt-schd-info-v2`)를 씁니다. 기상청과 같은 인증키(`SEA_KMA_KEY`)를 쓰며, **data.go.kr에서 이 API 활용신청(자동승인)이 승인돼 있어야** 값이 나옵니다. 운항구분 `정상·증선·증회`는 운항, `통제`는 통제, `비운`은 비운항으로 묶고, 통제·비운 사유를 함께 표시합니다. 대청도는 인천-백령 여객선이 경유하는 섬이라 스케줄에 따로 나오지 않아 `인천-백령 항로 경유`로 표시합니다.
- `firebase-rules.txt`는 Firebase 콘솔에 붙여넣는 보안 규칙 원본입니다(웹 화면에서는 쓰이지 않습니다).
- 저장소를 고쳐도 Pages 반영까지 1분 안팎 걸릴 수 있습니다.
- 당직 자동 배정은 평일(주말·공휴일·행사일 제외)만 대상으로 하며, 12월은 명단 처음부터, 1월 이후는 전달 마지막 당직자 다음 사람부터 이어집니다. 재배정에서는 시작 담당자를 직접 골라 그 사람부터 다시 돌릴 수 있습니다.
- 앱 권한은 **관리자**(승인·권한 부여)와 **당직 관리**(명단·재배정·행사일·자동 배정)로 나뉘고, 직책(position)과는 별개입니다.
- 회원가입은 **이름 · 사번 · 비밀번호**만 받습니다. 직책은 가입 직후 빈 값으로 두고, 관리자가 [팀원·설정]에서 지정합니다(관리자 본인 직책은 자기 카드·[내 정보]에서 직접).
- 비밀번호는 **4자리 이상**이면 됩니다. Firebase Auth 는 6자 미만을 거부하므로 앱이 4~5자리 비밀번호에만 고정 접미사 `__th`를 붙여 6자 이상으로 만들어 넘깁니다(6자 이상은 그대로 전달 — 기존 계정 그대로 로그인). Firebase 콘솔에서 비밀번호를 직접 다룰 때는 이 접미사를 기억해야 합니다.
- 공휴일은 내장 표(2026~2028, 한국천문연구원 월력요항 기준)와 연도별 온라인 자료(`date.nager.at`)를 합쳐 씁니다. 한 번 받은 연도는 브라우저에 캐싱되고, 내장 표가 있는 날짜는 내장 표를 우선합니다.
